# M4a: peer forks and merge

`imp fork "task"` clones the current persisted Pi branch at its leaf with Pi's
`SessionManager.createBranchedSession`. The clone preserves the complete prefix
byte-for-byte: system prompt, tools and their ordering, extension list, and
branch entries are unchanged. Its suffix starts with `familiar.fork.v1`, then a
model-visible `familiar.fork-note.v1`, then the task. Forks have private
`state/forks/<session-id>/{pi,presence,subconscious,golem-settlement}` roots and
private logs. The copied Pi settings/auth/model files and identical launch
arguments keep prompt construction equal. The subscriber extension remains
loaded and registers each fork as its own gateway session channel. Depth
defaults to two (`FAMILIAR_FORK_MAX_DEPTH`).

`imp merge [--quiet]` takes no summary. It records
`familiar.merge-pending.v1` and lets the current work turn finish. The harness
then disables every tool and starts one custom-message turn asking the fork to
write its return to the parent in its own voice. That final assistant message is
the complete merge summary without any generated prefix or suffix. The durable
`familiar.merge-return-requested.v1` marker makes an idle restart resume at the
correct phase: request the return again if it was not written, or send an
already-written return without generating another one.

Once the return turn settles, the scheduler `merge` event includes source
session/file, branch and actual first/last entry IDs, divergence, whether this
fork created a child, and the fork-side `mergedAt`. Its `lastEntryId` is the
return assistant entry. Empty output becomes `(no return written)`. The default
wake delivery persists a visible, turn-triggering `familiar.merge.v1` custom
message. `--quiet` uses scheduler urgency `soft`: it passes DND, persists the
same custom message with Pi's `nextTurn` delivery, and does not wake or trigger
the parent. The scheduler event is acknowledged only after that queued message
is visible in the durable parent branch, so a Pi restart before the next user
turn causes safe redelivery. The fork then records `familiar.merge-sent.v1` and
shuts down cleanly; nothing follows that marker.

An operator can start exactly the same content-neutral flow with
`POST /merge?session=<fork-id>` (optional JSON body `{"quiet":true}`). The
gateway rejects primary sessions because they have no parent and sends a
`{type:"merge", quiet?}` command down only the selected session's relay. An
idle fork starts the prompt immediately; an active fork waits for
`agent_settled`. Every fork returns by merge; there is no close operation.
`imp forks` reports state directories and
`systemctl is-active`. Calling merge at top level is refused. Continuity import
reconciles fork and merge records after every pass (while remaining tolerant of
historical close markers); unavailable references remain unresolved and are
retried, never inferred.

## fort-nix fork unit

The operator-owned template must set the following exact runtime contract (the
primary M3 unit remains separate). `fork-unit.sh` reads only the generated
`fork.json`; `Restart=on-failure` leaves a completed fork stopped.

```nix
systemd.services."familiar-pi@" = {
  description = "Familiar peer Pi %i";
  serviceConfig = {
    Type = "forking";
    User = "familiar";
    WorkingDirectory = "/var/lib/familiar/instances/kestrel";
    PIDFile = "/var/lib/familiar/instances/kestrel/state/forks/%i/presence/pi.pid";
    ExecStart = "${familiar}/scripts/fork-unit.sh start";
    ExecStop = "${familiar}/scripts/fork-unit.sh stop";
    Restart = "on-failure";
    RestartSec = "1s";
    KillMode = "control-group";
  };
  environment = {
    FAMILIAR_REPO = "${familiar}";
    FAMILIAR_CONFIG_PATH = "/var/lib/familiar/instances/kestrel/familiar.toml";
    FAMILIAR_STATE_DIR = "/var/lib/familiar/instances/kestrel/state";
    FAMILIAR_FORK_ID = "%i";
    FAMILIAR_SERVICES_SOCKET = "/run/familiar-services/familiar.sock";
    FAMILIAR_INTERACTIVE_SHELL = "${pkgs.bashInteractive}/bin/bash";
    PI_PACKAGE_DIR = "${pi}/lib/node_modules/pi-monorepo";
    FAMILIAR_FORK_HELPER = "${familiar}/scripts/fork-session.mjs";
    FAMILIAR_FORK_MAX_DEPTH = "2";
  };
  # Copy the primary unit's provider/router/plugin/identity variables here
  # unchanged (including FAMILIAR_PI_EXTRA_EXTENSIONS_JSON and plugin env).
  # Different values can change the prompt or registered tool schemas.
  path = [ pkgs.bashInteractive pkgs.coreutils pkgs.git pkgs.jq pkgs.nodejs pkgs.tmux ];
};
```

A sandbox must use temporary state/socket directories and fake `systemctl`,
router, and scheduler endpoints. Its prefix assertion compares the inherited
`familiar.system-prompt.v1.data.sha256` in parent and fork (that digest includes
the assembled prompt/tool surface), then verifies fork, merge enqueue, parent
`familiar.merge.v1`, and clean stop. Never point such a run at `/var/lib/kestrel`,
`/run/familiar-services`, or production units.

## Scheduled forks

`imp schedule --every RULE|--at TIME|--in D --fork [--label L] "task"` asks familiar-services to fork the primary in the background at that time (recurring with `--every`; rule grammar and catch-up policy in familiar-services `docs/M2.md`). From inside a fork, the target defaults to the root primary: a fork's schedule outlives the fork.

On delivery, the primary's scheduler extension waits until the primary is idle, so the branch point is a settled turn, then runs `imp fork --origin schedule:<series> --label <label> <preamble + task>`. It takes no model turn. It records `familiar.scheduled-fork.v1 {id, forkId, series, task}` as a non-model custom entry before acking, so a crash-and-redeliver can't spawn twice. Then it sends a quiet (nextTurn) "scheduled fork … started" note, so the primary finds out with Kev's next message. The fork's `fork.json` carries `label` and `origin` from birth, so the Open card shows it titled.

Scheduled forks pass DND: spawning one interrupts nothing, and its merge obeys DND like any other. `imp schedule list [--all]` shows kind (wake/soft/fork/merge), next fire in local time, the rule, and the target. `imp schedule cancel` on any occurrence stops the series.

## Fresh forks, declared models, and runners

`imp fork` (and `imp schedule --fork`) take three optional shapes:

- `--fresh`: the fork inherits only the system prompt (Pi supplies it) and the
  task, not the parent's conversation. Its session records where the parent was
  (`branchEntryId`) and is pinned to the parent's current model and thinking
  level, since a new session would otherwise fall back to the settings default.
  A fresh fork still meets the three conditions (Kes's prompt, a model that can
  carry her, it merges home): it is Kes with less context, and it is a fork.
- `--model PROVIDER/MODEL`: pins the fork's model. It must be on the allowlist
  of models considered able to carry Kes, `FAMILIAR_FORK_MODELS`
  (comma-separated patterns, `*` wildcard; unset = the built-in list in
  `branch.go`: the engines Kev has seen realize Kes, including the two local
  Qwens. The bar is "sufficient to be her", not "the most capable yet").
- `--runner`: required for a `--model` that is not on that list. The fork is
  recorded as `role: "runner"` in fork.json and its marker, its note tells it
  plainly that it is not Kes, and its return reaches the parent prefixed
  `[runner on <model>, not Kes]`. A lighter model never quietly wears her name.

`imp schedule --fork` validates the model at scheduling time, so a refusal
happens when the schedule is written, not at 6am.
